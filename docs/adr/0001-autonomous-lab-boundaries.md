# Isolate autonomous improvement from production and benchmark authority

The Local Knowledge development lab may automatically promote a better candidate only as its own incumbent; production deployment requires separate approval. Improvement agents may change plugin code, indexing/enrichment logic, and plugin-owned configuration, but not the frozen artifact sources, benchmark questions, expected targets, or scoring rules. A fixed evaluator outside the candidate's editable worktree establishes promotion evidence rather than trusting an agent's self-reported score.

We chose this boundary over automatic production deployment and a wholly agent-editable experiment because repeated unattended changes must not turn a benchmark win into production risk or make the test easier instead of the retrieval better. General candidate-generated enrichment is permitted; benchmark-question/answer lookup tables are not.

The benchmark consists of five valid, distinct realistic question intents per artifact, generated with Luna and followed by evidence-based AI validation. Unsupported questions are rejected and replaced, justified alternative targets are explicit, and AI judgments are not described as human gold. Freeze three development questions and two validation questions per artifact. Development cases are available to improvement agents; validation questions, targets, and per-case failures remain outside worker access, with aggregate validation metrics disclosed. Repeated validation can still cause indirect overfitting, so success establishes performance on this frozen campaign rather than universal search quality.

Use fresh Docker containers per experiment from a pinned lab image containing unmodified official Hermes and development/test tools, replacing the earlier dedicated-VM requirement. Run on the current Hermes host using its existing rootful Docker engine, with Docker control restricted to the trusted external controller and never exposed to workers. This avoids extra infrastructure provisioning while explicitly accepting shared-kernel/shared-host risk. The runtime and corpus remain fixed while the starting plugin advances with the incumbent, supplied separately in a fresh writable workspace. Persist reports/checkpoints outside disposable containers and keep the controller/evaluator outside worker access; run exact-revision tests in a separate clean evaluation container. This gives simpler clean starts and reproducibility without rebuilding the image for each promotion. Containers share the host kernel, so they are not VM-equivalent security boundaries: workers must be non-root, unprivileged, resource-limited without a time limit, unable to control Docker or access production mounts/credentials, and network-restricted from homelab services. Supply necessary model authentication separately, not in the image. Score one public plugin search per fixed question, using candidate-built indexes over the frozen sources and clean feedback state rather than conversational retries or learning from evaluation searches.

The promotion gate requires strictly higher validation Hit@5 over evidence-validated acceptable targets, no Hit@1 decrease on either development or validation, warm public-search p95 latency at most one second, passing tests and official-Hermes installation/integration checks, and independent review. Exact originating-artifact Hit@5 remains a separate reported metric. Equal scores do not promote; one additional successful validation question can qualify without establishing universal or statistical superiority. The latency limit includes query-time model work and excludes index construction; it is an adopted lab requirement, not a previously verified production guarantee.

Implementation and independent review use separate sessions pinned to `gpt-6.1-sol` / `openai-codex`, reasoning `high`. There is no time limit or separately enforced monetary/token allowance. Hourly ticks skip while busy rather than overlapping runs or killing a long experiment. Report provider-reported usage and pause with an alert on exhausted quota or persistent authentication failure.
